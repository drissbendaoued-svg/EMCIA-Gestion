# EMCIA Gestion 2026.11.17.2

Learners billed per completed lesson now appear beside monthly learners in a shared account table, including learners with no payments or no completed lessons yet. The table is reused in learner files, teacher files, group reports, analysis, budget and administrative reports. Teacher statements include both billing modes and outstanding amounts without revealing the institution's share.

## Accounting and exports

- A read-only account model separates tuition due, amounts allocated to tuition, actual cash received, outstanding debt and unused advance/excess credit. Each learner/group/billing-mode combination has its own balance; advances never cancel another account's debt.
- The comprehensive teacher file previously counted a session receipt and its recognition allocation as receipts twice. Cash now comes only from the original monthly/session payment records. Completed-and-collected sessions alone earn teacher/institution shares.
- Monthly payment allocations, net refunds, existing discount/settlement rules and saved teacher/institution share amounts remain in use. Session allocation and rounding rules remain unchanged.
- Arrears, detail dialogs and reminder drafts now include session balances. Reminders are still manually prepared.
- The learner file includes one combined receipt history and combined headline balances.
- Printed administrative/financial/arrears reports include the unified table inside the `.rc-paper` element used by print and download. Previously, session balances were appended outside this export boundary, so they could appear in preview and disappear in exports.
- Teacher payout confirmation and the actual amount received by the teacher remain separate from the calculated teacher share. No underlying learner/payment/attendance records or live database were changed.
