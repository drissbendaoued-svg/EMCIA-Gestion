# EMCIA Gestion — 2026.11.14.1

## Published source

`emcia.html` is the canonical app, based on the latest certification/session-payment build. The index, Cloud Test, Director Test, certification integration/issuance, and release-candidate URLs redirect to it. Redirects preserve query parameters and authentication fragments; the `v` parameter reflects the actual release. Independent certificate printing/verification pages and backup files are unchanged.

## Corrections

- Strict calendar-date validation for session payment creation/editing.
- Receipt numbers checked across monthly and session receipts.
- Actual cash and shift receipts include session payments, while their teacher-remuneration allocation remains unactivated.
- Timed attendance change handlers escape their embedded JSON arguments correctly.
- Timed records are used by attendance reports; superseded legacy day records are excluded, without deleting historical data.
- A timetable session's completion status reads that particular session, not another session in the same group/day.
- Explicitly absent/excused flexible lessons are excluded from session estimates. Existing flexible entries without a timed record retain their original meaning of completed lessons.
- The legacy daily entry form is hidden when a scheduled session exists for the selected group/day. Timed entries remain independent.
- Timetable edits ignore their own record during conflict checks and validate days/times. Adjacent flexible lessons are allowed. Schedule deletion archives the entry to preserve references from attendance history.
- Financial sidecar fields are written with `_id` and resolved using stable record IDs. A durable `_legacyFinancialIds` map maintains old `_index` records across subsequent operational deletions.

## Validation

`npm ci && npm test` runs synthetic DOM/authentication/synchronization integration tests. All fetches are intercepted in-memory; tests do not contact production services. Tests cover input event handlers, separate attendance at different times on one day, payment creation/editing and reload, invalid dates, duplicate receipts, cash totals, schedule conflict checks, financial legacy compatibility after a secretary deletes an earlier record, and stable new financial IDs.

## Remaining work

- Production role/RLS tests and database-level atomic saving require a working Supabase administration connection. Operational and financial writes remain sequential; existing revision checks and conflict blocking remain active. This release does not claim transactional saving.
- Full financial recognition of session receipts and teacher entitlements is still pending. Actual cash receipts are included in cash control; financial remuneration reports retain their existing scope.
- Historical data that was already misassociated before this release needs a separate reconciliation; introducing stable IDs cannot identify earlier incorrect associations.
- Historical day-only attendance cannot establish the time of multiple lessons. It remains available as legacy history, rather than being duplicated across all scheduled lessons.
- Visual testing on real phones and real account checks remain to be completed; local Chromium could not launch in this environment. DOM event/integration tests ran with jsdom.
