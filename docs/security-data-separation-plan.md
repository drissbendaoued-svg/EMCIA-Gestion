# EMCIA Gestion — خطة فصل البيانات والصلاحيات (2026-11-08)

## نتيجة الفحص
- التخزين الحالي: صف واحد في public.emcia_cloud_state يحمل payload JSON موحداً.
- المتصفح يجلب payload كاملاً عند تسجيل الدخول ويحفظه في localStorage باسم emcia_core_mobile.
- يمكن لأدوار السكرتارية قراءة هذا الصف وفق RLS الحالية. لذلك إخفاء الميزانية والتحليل المالي من الواجهة ليس عزلاً للبيانات.
- المزامنة الحالية تكتب payload كاملاً مع revision متزايد؛ لا يجوز قطع الوصول إلى الصف قبل تعديل العميل، وإلا سيتعطل الحفظ.
- الجداول التشغيلية الأخرى لديها سياسات RLS؛ يجب تدقيقها بصورة مستقلة.

## التصميم المستهدف
1. بيانات تشغيلية مشتركة: المواد والأساتذة والمتعلمون والأفواج والتسجيلات والحضور والجداول والأداءات اللازمة للعمل اليومي.
2. بيانات مالية مقيدة: المصاريف والمداخيل الأخرى والادخار والتسويات والمستحقات والتقارير المالية الحساسة. الوصول للمدير والمحاسب فقط، وفق سياسات RLS على الخادم.
3. يجب تصنيف كل حقل، لا مجرد كل مجموعة بيانات، لأن سجلات الأداء قد تحتوي على حصة الأستاذ وحصة المؤسسة.
4. تجنب وضع بيانات مقيدة في أي payload أو endpoint يمكن للكاتبتين قراءته؛ لا تعتمد على تنقية العرض في JavaScript.
5. فصل المزامنة إلى مجموعتي revision مستقلتين أو جداول تشغيلية/مالية منفصلة، مع ضمان عدم ضياع تحديثات متزامنة.

## معيار القبول
لا تستطيع حسابات السكرتارية قراءة البيانات المالية المقيدة عبر API أو الواجهة أو النسخ الاحتياطية، وتظل التسجيلات والأداءات والحفظ والمزامنة تعمل بصورة صحيحة. لا تغيير على الحسابات المالية أثناء النقل.
