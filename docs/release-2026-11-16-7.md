# Release 2026.11.16.7

Waiting lists now form independent material/level cohorts from each learner’s requested subject-level pairs, with legacy learner-level fallback. Common BAC aliases and language-level casing are normalized for grouping; broad or absent levels remain separate and cannot prepare a group. Equivalent duplicate requests for the same learner/material/level count once. Enrollment at another level no longer removes a waiting request. Counts distinguish requests, unique learner IDs, and actual waiting versus reason-excluded requests.

Add exact level and timing filters plus name/phone search, cohort timing breakdowns and a grouped global summary. Day/evening filters include flexible preferences. Each learner has visible tap-to-call personal/guardian/landline links, explicit missing-phone notices and an edit-contact shortcut. Cohorts are collapsible and remain open during follow-up changes.

Target count, proposed teacher, first-session date and notes are saved per cohort (and timing filter when selected); rendering does not create configuration records. Legacy material-wide non-enrollment reasons remain readable, with level-specific overrides that preserve other levels. Group preparation prefills material/level and an existing proposed teacher; no group or enrollment is created until explicitly saved.

Validation: full application JavaScript compiled for syntax in the hosted runtime. The new standalone waiting-groups test was executed in the hosted runtime against the final source, covering aliases, per-subject levels, deduplication, enrollment at another level, counts, timing/name/phone filters, independent exclusions, preserved legacy reasons, phone links, missing phones, handler syntax, read-only refresh and separate cohort targets. It is included in npm test. The full DOM/auth integration suite was not rerun because the executor was unavailable. No production records were modified.
